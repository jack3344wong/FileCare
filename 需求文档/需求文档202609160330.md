### 2.2 后台运行与系统托盘 ⏳ **待开发**

#### 2.2.1 功能描述
用户关闭窗口后，软件不退出，而是在系统托盘区域保持运行，可随时恢复窗口。

#### 2.2.2 功能要点

**窗口关闭行为**：
- 点击窗口关闭按钮（X）时，默认最小化到托盘
- 可在设置中选择"直接退出"或"最小化到托盘"
- 按住 Shift 键点击关闭按钮时强制退出（快捷操作）

**系统托盘图标**：
- 显示软件图标（使用 assets 中的图标资源）
- 鼠标悬停显示软件名称和版本
- 左键单击：恢复/最小化主窗口
- 右键单击：弹出菜单

**托盘菜单项**：
- 打开主界面
- 快速扫描（子菜单：扫描全盘/扫描用户目录）
- 暂停/恢复扫描
- 设置
- 检查更新
- 退出

**后台运行行为**：
- 主窗口隐藏，但进程保持运行
- 后台任务继续执行（如索引扫描、更新检查）
- 内存占用优化（隐藏窗口时释放部分资源）
- 支持从托盘菜单快速恢复窗口

#### 2.2.3 技术实现要点
- 使用 PyQt5 的 `QSystemTrayIcon` 类
- 重写 `closeEvent` 拦截关闭事件
- 托盘图标支持动画效果（扫描时）
- Windows 10/11 通知中心集成（可选）

#### 2.2.4 验收标准

### 2.3 开机自启动 ⏳ **待开发**

#### 2.3.1 功能描述
用户可选择让软件在系统启动时自动运行，启动后可直接最小化到托盘。

#### 2.3.2 功能要点

**实现方式**：
- Windows 注册表方式（推荐）：`HKEY_CURRENT_USER\Software\Microsoft\Windows\CurrentVersion\Run`
- 备选方案：启动文件夹（`shell:startup`）
- 使用当前用户权限，不需要管理员权限

**配置选项**：
- 开机启动开关（在设置页面）
- 启动后行为：显示主窗口 / 最小化到托盘（默认）
- 延迟启动（可选，避免系统启动时资源竞争）

**注册表项**：
- 键名：`FileCare`
- 键值：`"C:\Program Files\FileCare\filecare.exe" --minimized`
- 支持命令行参数控制启动行为

**权限处理**：
- 写入当前用户注册表（HKCU），无需 UAC 提权
- 如果安装到系统目录，使用 HKCU 而非 HKLM
- 卸载时自动清理注册表项

#### 2.3.3 验收标准
- [ ] 设置页面可开关开机启动功能
- [ ] 开启后重启系统，软件自动运行
- [ ] 启动后可选择显示窗口或最小化到托盘
- [ ] 关闭功能后重启系统，软件不自动运行
- [ ] 不弹出 UAC 提权对话框
- [ ] 卸载软件后注册表项自动清理
- [ ] 支持 Windows 7/8/10/11

### 2.4 官方网站与更新系统 ⏳ **待开发**

#### 2.4.1 功能描述
在阿里云服务器上部署官方网站，提供软件介绍、下载、更新提醒等功能。

#### 2.4.2 官网功能

**页面结构**：
- 首页：软件介绍、核心功能展示、下载按钮
- 下载页：最新版本下载、历史版本、更新日志
- 帮助页：使用教程、常见问题
- 关于页：版本信息、开源协议、联系方式

**技术选型**：
- 前端：静态 HTML + CSS + JavaScript（或 Vue/React 单页应用）
- 后端：Python Flask / FastAPI（与项目技术栈一致）
- 数据库：SQLite（轻量）或 MySQL（如需多用户）
- 部署：Nginx + Gunicorn / uWSGI
- SSL：Let's Encrypt 免费证书

**下载功能**：
- 提供最新安装包下载（`FileCare-Setup-x.x.x.exe`）
- 显示文件大小、MD5/SHA256 校验和
- 支持断点续传（HTTP Range 请求）
- 下载统计（可选）

**更新检测接口**：
- API 端点：`/api/version/latest`
- 返回格式：JSON
  ```json
  {
    "version": "1.2.0",
    "release_date": "2026-09-20",
    "download_url": "https://example.com/downloads/FileCare-Setup-1.2.0.exe",
    "changelog": "修复了xxx问题，新增了xxx功能",
    "mandatory": false
  }
  ```
- 支持版本比较（语义化版本 SemVer）

#### 2.4.3 客户端更新功能

**更新检测**：
- 启动时自动检查更新（可在设置中关闭）
- 手动检查更新（托盘菜单 / 帮助菜单）
- 检测间隔：每天最多一次（避免频繁请求）

**更新提醒**：
- 发现新版本时弹通知
- 显示版本号、更新日期、更新内容摘要
- 提供"立即更新"、"稍后提醒"、"跳过此版本"选项
- 强制更新时（`mandatory: true`）不显示"跳过"选项

**下载与安装**：
- 点击"立即更新"后下载安装包
- 下载进度条显示
- 下载完成后提示运行安装程序
- 可选：静默安装（`/SILENT` 参数，需 Inno Setup 支持）

**版本管理**：
- 客户端版本号：从 `__version__` 或资源文件读取
- 服务器版本号：数据库或配置文件维护
- 版本比较：支持主版本号.次版本号.修订号（如 1.2.0）

#### 2.4.4 服务器部署

**服务器要求**：
- 阿里云 ECS（已有）
- 操作系统：Ubuntu 20.04 / CentOS 7+
- 配置：1核2G 起步（静态网站 + 轻量 API）
- 带宽：3Mbps+（考虑下载流量）
- 域名：建议备案后使用（如 `filecare.cn`）

**部署架构**：
```
用户浏览器 → Nginx（静态文件 + 反向代理）
              ↓
         Gunicorn（Flask API）
              ↓
         SQLite（版本信息）
```

**目录结构**：
```
/var/www/filecare/
├── static/          # 静态文件（HTML/CSS/JS/图片）
├── downloads/       # 安装包文件
│   ├── FileCare-Setup-1.1.0.exe
│   └── FileCare-Setup-1.2.0.exe
├── api/             # Flask 应用
│   ├── app.py
│   └── versions.db
└── logs/            # 访问日志
```

**维护操作**：
- 发布新版本：上传安装包到 `downloads/`，更新数据库
- 提供管理脚本：`python manage.py release --version 1.2.0 --file xxx.exe`
- 可选：Web 管理后台（上传安装包、编辑更新日志）

## 六、风险与注意事项

### 6.1 技术风险
- **托盘图标在某些系统不显示**：需要提供备用方案（任务栏图标）
- **注册表权限问题**：使用 HKCU 避免 UAC，但需测试不同 Windows 版本
- **服务器带宽不足**：大文件下载可能卡顿，建议使用 CDN 或对象存储

### 6.2 用户体验风险
- **后台运行占用资源**：需要优化内存和 CPU 占用
- **更新提醒过于频繁**：提供"稍后提醒"和"跳过版本"选项
- **设置项过多**：分类组织，提供"恢复默认"按钮

### 6.3 运维风险
- **服务器宕机**：更新检测失败时静默处理，不影响软件使用
- **域名备案**：国内服务器必须备案，否则无法使用域名
- **安装包上传错误**：提供校验和验证，发布前测试
